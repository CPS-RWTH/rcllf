# Features

One row per capability. "Status" is honest about what actually runs today versus what's
still in progress. See the linked page for details and current limitations.

For per-feature-module support (QoS hazard detection, core ROS 2 capabilities, and every
diagnostic code), see the auto-generated [Support Matrix](support-matrix.md).

| Capability | What it does | Status | Docs |
|---|---|---|---|
| **Extraction** (`colcon lf-analyze`) | Static analysis of a ROS 2 workspace's launch files, C++ node sources, and `CMakeLists.txt` into a unified `system.json` model (nodes, timers, subscriptions, services, actions, callback groups, parameters). | Stable for the patterns exercised by the example packages and validated against Nav2. Known gaps include lambda callbacks, full QoS profiles, tf2, and Python/rclpy nodes. | [Extraction Overview](../design/extraction.md) |
| **LF code generation** (`colcon lf-generate`) | Converts `system.json` into a real, compilable `.lf` [reactor](../design/glossary.md#reactor) program plus the C++ scaffolding (`ros2_lf_reaction_ids.h`, startup shims) needed to link it against `ros2_lf_binding`. | Stable. Timers, subscriptions, services (3-reaction handshake), actions (5-reaction model), and callback-group mapping are all implemented. | [LF Code Generation](../design/lf-generation.md) |
| **lfc compilation & execution** | `colcon build` invokes `lfc` to compile the generated `.lf` into C++ and link it against `ros2_lf_binding`. The resulting binary runs entirely under the reactor-c scheduler with no `rclcpp::Executor` in the loop. | Stable, sole runtime path. | [lfc Path Internals](../design/architecture.md) |
| **Launch generation** | Emits a ROS 2 launch file (or, for component nodes, relies on `ros2 lf launch`) so the generated system can be started the same way any ROS 2 system is. | Stable for the example packages and the reference system. | [CLI Reference](../reference/cli.md) |
| **Callback groups** | Maps ROS 2 `MutuallyExclusive` and `Reentrant` callback groups onto LF sub-reactors, preserving ROS 2's intra-group / cross-group concurrency semantics. | Stable, with one explicit restriction: LF reactors are singletons, so ROS 2's same-callback self-concurrency isn't reproduced automatically (a documented reactor-bank escape hatch exists). | [Callback Groups](../design/callback-groups.md) |
| **Federation** (multi-process) | Splits a generated LF program across multiple OS processes ([federates](../design/glossary.md#federate-federation)), coordinated by the LF [Run-Time Infrastructure (RTI)](../design/glossary.md#rti-run-time-infrastructure) daemon ([centralized coordination](../design/time-and-coordination.md#regime-2-federated-centralized)), while DDS continues to carry all data. Strictly opt-in via `--federate`. | Available and opt-in. Federation is all-or-nothing. Every declared federate must be present for the program to make progress. | [Federation](federation.md) |
| **Fast mode** (`--fast`, `--timeout`) | Runs a generated program faster than physical time: logical time advances as soon as the reactions are done, and `--timeout` ends the program at a logical time instead of a wall-clock signal. Also settable at launch through `RCLLF_LF_ARGS`. | Available for the one program (pilot: about 4.5x faster than real time, outputs identical to the real-time runs) and for centralized federations (about a quarter of the wall time; a cross-federate sample can arrive after its tag is granted and is then reported lost, see the page). | [Fast Mode](fast-mode.md) |
| **Plants** (`rcllf_plant`) | Every simulated plant runs behind one Transactor: one checked request per step, the node keeps the clock, a stuck plant times out and the node fails closed. One `plant_step` log line per step carries a hash of the full plant state, so runs compare step by step from their logs. | Available with MuJoCo 3.14.0 for the `brake_fusion` vehicle (milestone M1). | [Plants](plants.md) |
| **Visualizations** | Renders four Graphviz DOT graph types (launch hierarchy, communication graph, per-node internals, unified system graph) from the extracted JSON model, as PDF/SVG. | Stable. Some extracted fields (remappings, launch arguments, composable-container membership) aren't visualized yet. | [Visualizations](visualizations.md) |
| **Tracing** | LTTng-based tracing across all containers sharing a host PID namespace (`docker/trace.sh`), capturing ROS 2 tracepoints for post-hoc analysis via the `lf-eval` CLI (trace → metrics → plots in one command). | Available via `docker compose up tracer`. Four metrics (`e2e_latency`, `determinism`, `cpu`, `drops`) shipped in `tools/lf_eval`. | [Tracing](tracing.md) |
